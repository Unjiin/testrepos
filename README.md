# 📘 Git Bash — шпаргалка по Git

> Краткая шпаргалка по основным Git-командам.  
> Самые часто используемые команды находятся в начале, более редкие — ближе к концу.

---

## 🚀 Самые нужные команды

### Проверить состояние репозитория

```bash
git status
```

Показывает:

- изменённые файлы;
- новые файлы;
- файлы, добавленные в индекс;
- текущую ветку.

---

### Добавить файл в индекс

```bash
git add filename
```

Например:

```bash
git add README.md
```

Добавить **все изменённые файлы**:

```bash
git add .
```

> `git add` подготавливает изменения к коммиту.

---

### Создать коммит

```bash
git commit -m "Описание изменений"
```

Пример:

```bash
git commit -m "Добавил шпаргалку по Git"
```

Хорошее сообщение коммита должно коротко объяснять, что было сделано.

---

### Отправить изменения на GitHub

```bash
git push
```

При первой отправке новой ветки:

```bash
git push -u origin branch-name
```

---

### Получить изменения с GitHub

```bash
git pull
```

Команда скачивает изменения и пытается объединить их с локальной веткой.

---

## 📂 Создание и клонирование репозитория

### Создать новый локальный Git-репозиторий

```bash
git init
```

После выполнения Git создаст скрытую папку `.git`.

---

### Клонировать существующий репозиторий

```bash
git clone URL
```

Пример:

```bash
git clone https://github.com/username/project.git
```

После этого появится папка с проектом и всей историей коммитов.

---

## 🔗 Работа с удалённым репозиторием

### Посмотреть подключённые удалённые репозитории

```bash
git remote -v
```

Обычно основной удалённый репозиторий называется:

```text
origin
```

---

### Добавить удалённый репозиторий

```bash
git remote add origin URL
```

Пример:

```bash
git remote add origin https://github.com/username/project.git
```

---

### Изменить URL удалённого репозитория

```bash
git remote set-url origin URL
```

---

### Удалить удалённый репозиторий

```bash
git remote remove origin
```

---

## 🌿 Работа с ветками

### Посмотреть список веток

```bash
git branch
```

Текущая ветка будет отмечена символом `*`.

---

### Создать новую ветку

```bash
git branch branch-name
```

Пример:

```bash
git branch feature
```

---

### Переключиться на ветку

```bash
git switch branch-name
```

Старый вариант:

```bash
git checkout branch-name
```

---

### Создать ветку и сразу перейти в неё

```bash
git switch -c branch-name
```

Старый вариант:

```bash
git checkout -b branch-name
```

---

### Удалить локальную ветку

```bash
git branch -d branch-name
```

Принудительное удаление:

```bash
git branch -D branch-name
```

> `-D` удаляет ветку даже если её изменения ещё не были объединены.

---

## 🔀 Объединение веток

Допустим, нужно перенести изменения из ветки `feature` в `main`.

Сначала переходим в `main`:

```bash
git switch main
```

Затем выполняем:

```bash
git merge feature
```

После успешного объединения ветку `feature` при необходимости можно удалить:

```bash
git branch -d feature
```

## 📜 История коммитов

### Полная история

```bash
git log
```

---

### Короткая история

```bash
git log --oneline
```

Пример:

```text
a13f2b1 Добавил README
21ac932 Исправил ошибку
5fc4420 Initial commit
```

---

### История в виде графа

```bash
git log --oneline --graph --all
```

Удобно при работе с несколькими ветками.

---

## 🔍 Просмотр изменений

### Посмотреть изменения, которые ещё не добавлены через `git add`

```bash
git diff
```

---

### Посмотреть изменения, которые уже добавлены в индекс

```bash
git diff --staged
```

---

## ↩️ Отмена изменений

### Отменить изменения в файле

```bash
git restore filename
```

Пример:

```bash
git restore README.md
```

> Осторожно: несохранённые изменения в файле будут потеряны.

---

### Убрать файл из индекса после `git add`

```bash
git restore --staged filename
```

Пример:

```bash
git restore --staged README.md
```

Изменения в самом файле останутся.

---

## ⏪ Работа с коммитами

### Изменить последний коммит

Например, если забыли добавить файл:

```bash
git add filename
git commit --amend
```

Изменить только сообщение:

```bash
git commit --amend -m "Новое сообщение"
```

---

### Отменить коммит безопасным способом

```bash
git revert HASH
```

Пример:

```bash
git revert a13f2b1
```

Git создаст **новый коммит**, который отменяет изменения старого.

---

### Переместиться к старому коммиту

```bash
git reset --soft HASH
```

Коммит отменится, но изменения останутся в индексе.

```bash
git reset --mixed HASH
```

Коммит отменится, изменения останутся в файлах.

```bash
git reset --hard HASH
```

Коммит и изменения будут удалены.

> ⚠️ `git reset --hard` нужно использовать осторожно: можно потерять изменения.

---

## 📥 Получение изменений без автоматического слияния

```bash
git fetch
```

Команда скачивает информацию с удалённого репозитория, но не изменяет текущие файлы.

После этого можно посмотреть удалённые ветки:

```bash
git branch -r
```

---

## 🧩 Конфликты

Конфликт может возникнуть, когда разные изменения были сделаны в одном месте файла.

Git покажет примерно такое:

```text
<<<<<<< HEAD
мой вариант
=======
другой вариант
>>>>>>> feature
```

Нужно вручную оставить правильный вариант, удалить служебные строки, затем:

```bash
git add .
git commit -m "Resolve merge conflict"
```

## 🗑️ Удаление файлов

Удалить файл и сразу сообщить об этом Git:

```bash
git rm filename
```

После этого:

```bash
git commit -m "Удалил файл"
```

---

## ✏️ Переименование файла

```bash
git mv oldname newname
```

Пример:

```bash
git mv test.txt info.txt
```

---

## 📌 `.gitignore`

Файл `.gitignore` содержит файлы и папки, которые Git не должен отслеживать.

Пример:

```gitignore
.idea/
cmake-build-debug/
*.log
.env
node_modules/
```

После добавления файла в `.gitignore` Git перестанет отслеживать **новые** файлы, подходящие под эти правила.

## 🏷️ Теги

Посмотреть теги:

```bash
git tag
```

Создать тег:

```bash
git tag v1.0
```

Отправить тег на GitHub:

```bash
git push origin v1.0
```

Отправить все теги:

```bash
git push --tags
```

## 🧹 Временное сохранение изменений — stash

Если нужно временно убрать незаконченные изменения:

```bash
git stash
```

Посмотреть сохранённые изменения:

```bash
git stash list
```

Вернуть последние изменения:

```bash
git stash pop
```

## ⚙️ Первоначальная настройка Git

Указать имя:

```bash
git config --global user.name "Your Name"
```

Указать email:

```bash
git config --global user.email "example@mail.com"
```

Проверить настройки:

```bash
git config --list
```

## 📁 Навигация в Git Bash

Git Bash поддерживает обычные Linux-команды.

### Показать текущую папку

```bash
pwd
```

### Посмотреть содержимое папки

```bash
ls
```

Подробный список:

```bash
ls -la
```

### Перейти в папку

```bash
cd folder
```

На уровень выше:

```bash
cd ..
```

В домашнюю директорию:

```bash
cd ~
```

### Создать папку

```bash
mkdir folder
```

### Создать пустой файл

```bash
touch file.txt
```

### Удалить файл

```bash
rm file.txt
```

### Удалить папку со всем содержимым

```bash
rm -rf folder
```

> ⚠️ `rm -rf` удаляет файлы без корзины.

### Очистить консоль

```bash
clear
```

## 🧠 Типичный порядок работы

Обычно работа с Git выглядит так:

```bash
git status
git add .
git commit -m "Описание изменений"
git push
```

Если работаем не один:

```bash
git pull
git status
git add .
git commit -m "Описание изменений"
git push
```

---

## 🌿 Пример работы с новой веткой

```bash
git switch main
git pull
git switch -c new-feature
```

Делаем изменения, затем:

```bash
git add .
git commit -m "Добавил новую функцию"
git push -u origin new-feature
```

После объединения изменений:

```bash
git switch main
git pull
git branch -d new-feature
```

## 📋 Мини-шпаргалка

| Команда | Что делает |
|---|---|
| `git status` | показывает состояние репозитория |
| `git add .` | добавляет изменения в индекс |
| `git commit -m "..."` | создаёт коммит |
| `git push` | отправляет коммиты на GitHub |
| `git pull` | получает изменения с GitHub |
| `git clone URL` | клонирует репозиторий |
| `git branch` | показывает ветки |
| `git switch name` | переключает ветку |
| `git switch -c name` | создаёт новую ветку |
| `git merge name` | объединяет ветки |
| `git log --oneline` | показывает историю |
| `git diff` | показывает изменения |
| `git restore file` | отменяет изменения файла |
| `git stash` | временно сохраняет изменения |
| `git remote -v` | показывает удалённые репозитории |

---

## ✅ Самая важная последовательность

```bash
git pull
git status
git add .
git commit -m "Что я сделал"
git push
```

> Главное правило: перед началом работы полезно делать `git pull`, а перед коммитом — проверять `git status`.
